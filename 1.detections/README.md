# 1. Detections. Threat-Centric Overview

## 🎯 Purpose
This section focuses on attack- and threat-centric detections relevant to SOC Analysts (L1).  
Each detection is organised around a specific attacker behaviour (e.g. LSASS credential dumping, authentication anomalies, PowerShell abuse), rather than around a particular SIEM.

---

## 📌 What This Section Covers
This folder helps you understand:

* How common attacks and threats appear in logs
* How each attack maps to MITRE ATT&CK tactics and techniques
* How the same threat can be detected across different platforms (Sentinel, Elastic, Sigma)
* How SOC analysts investigate and respond to alerts generated by these detections

> **Core Philosophy:** Attacker behaviour first, tooling second.

---

## 📁 Structure of Detection Subfolders
There are currently **five threat detection categories**, each named after the attack or behaviour:

* `lsass-credential-dumping/`
* `lsass-access/`
* `authentication-anomalies/`
* `powershell-encoded/`
* `registry-modification/`

Within each folder, you may find some or all of the following:

### 1. Threat Background (Theory)
Explains the attack, why it is dangerous, and how it manifests in logs.

### 2. Sentinel Detection
Human-readable documentation (`sentinel-rule.md`) and rule logic (`sentinel.yaml`) for Microsoft Sentinel.

### 3. Elastic / Sigma (Selected Examples)
Where relevant, additional examples showing how the same threat can be detected in Elastic (`elastic.md`) or expressed as a SIEM-agnostic rule (`sigma.yml`).

### 4. Evidence (Hands‑On)
All practical investigations, screenshots, and artefacts are stored in:

**`0.hands-on-evidence/`**

*This folder is now operational and contains real Sysmon/Wireshark artefacts from ongoing hands‑on practice. More evidence will be added progressively as learning and investigations continue.*

---

## 🎓 How This Section Supports SOC Work
By structuring detections around attacks and threats, this section mirrors how real SOC teams think:

* **Start from attacker behaviour:** Identify the TTPs.
* **Telemetry analysis:** Understand how it appears in logs and events.
* **Engineering & implementation:** Implement one or more detections across available tools.
* **Triage & response:** Investigate and respond based on the actual threat, not just the SIEM interface.
