# SOC Response Playbooks

This document contains standardised response playbooks used in a Security Operations Centre (SOC).  
Each playbook provides clear steps for triage, investigation, containment, eradication and recovery.

---

# 1. Authentication Anomaly Playbook

## 1. Triage
- Validate user identity and role.
- Check recent sign‑ins for impossible travel.
- Review MFA failures or fatigue patterns.
- Check IP reputation (TOR, VPN, known malicious ranges).

## 2. Investigation
- Build timeline using authentication logs.
- Pivot into DeviceProcessEvents for post‑login activity.
- Check for unusual process execution after login.
- Validate if the login was followed by lateral movement.

## 3. Containment
- Reset user password.
- Revoke active sessions and tokens.
- Enforce MFA reset.
- Block suspicious IP ranges.

## 4. Eradication
- Remove malicious scripts or tools.
- Patch vulnerable endpoints.
- Clean persistence mechanisms if found.

## 5. Recovery
- Re-enable account once safe.
- Monitor user activity for 24–48 hours.
- Update detection rules if needed.

# 2. PowerShell Encoded Execution Playbook

## 1. Triage
- Validate encoded command (`-enc`, `-encodedcommand`).
- Check process lineage (parent/child).
- Review ScriptBlockLogging for suspicious content.
- Identify device risk level.

## 2. Investigation
- Build timeline of PowerShell activity.
- Pivot into network logs for outbound connections.
- Check for downloads, IEX, or obfuscated payloads.
- Validate persistence (scheduled tasks, registry).

## 3. Containment
- Isolate device from network.
- Kill malicious processes.
- Block outbound IPs/domains.

## 4. Eradication
- Remove scripts, payloads, or scheduled tasks.
- Clean registry modifications.
- Patch system vulnerabilities.

## 5. Recovery
- Restore device connectivity.
- Re-enable user access.
- Add encoded command patterns to detection rules.

---

# 3. LSASS Access / Credential Dumping Playbook

## 1. Triage
- Validate LSASS access event.
- Check GrantedAccess values (`0x40`, `0x1000`, `0x1FFFFF`).
- Identify process attempting access (procdump, rundll32, comsvcs.dll).
- Assess device criticality.

## 2. Investigation
- Build timeline of LSASS access.
- Pivot into memory read events.
- Check for credential dumping tools.
- Review lateral movement attempts.

## 3. Containment
- Isolate device immediately.
- Disable compromised accounts.
- Block suspicious processes.

## 4. Eradication
- Remove dumping tools.
- Clean persistence mechanisms.
- Patch OS and security tools.

## 5. Recovery
- Reconnect device after validation.
- Reset all credentials.
- Add LSASS access patterns to detection rules.
