# Sysmon Event ID 8 : Electron Multi‑Process IPC Thread Creation (Visual Studio Code)

A clear and accessible SOC analysis for `CreateRemoteThread` events generated by Electron‑based applications.

## Overview
This case study explains why Visual Studio Code (VS Code) -built on the Electron/Chromium framework - legitimately creates remote threads between its own processes.
*_See glossary:_* 
[Electron IPC](/0.therory/glossary.md#electron-ipc)

Although Sysmon Event ID 8 is often associated with process injection, this behaviour is expected and safe within Electron’s multi‑process architecture.

## 1. Architectural Context : Electron’s Multi‑Process Model
VS Code runs on Electron, which uses a Chromium‑style multi‑process design:

* **Main Process** — coordinates the application
* **Renderer Processes** — UI, panels, editor windows
* **Extension Host** — runs VS Code extensions
* **GPU Process** — graphics and rendering tasks

Electron uses inter‑process communication (IPC) to coordinate work. One of the mechanisms used internally is remote thread creation, where the main process schedules tasks inside a child process. This is normal behaviour and not a sign of malware.

## 2. Forensic Verification

### Same Binary (`SourceImage == TargetImage`)
Both processes point to the same signed VS Code binary:
```text
C:\Users\magda\AppData\Local\Programs\Microsoft VS Code\Code.exe
```
This confirms intra‑application coordination, not cross‑process injection.

## Legitimate StartModule
The thread begins inside the `Code.exe` image base, not in:

* RWX memory
* `MEM_PRIVATE` regions
* unbacked memory
* suspicious DLLs

This is exactly what we expect from Electron’s IPC system.

## Identity Continuity
Source and target run under the same interactive user account:
```
Azul_Fifty\magda → Azul_Fifty\magda
```
* No privilege escalation.
* No integrity level jump.
* No SYSTEM‑level manipulation.

## 3. SOC Triage Perspective (MITRE ATT&CK T1055)
Related MITRE Technique: [T1055 Process Injection](/0.therory/glossary.md#mittre-attack)
Sysmon Event ID 8 is commonly used to detect:

* Cobalt Strike
* Process injection
* Credential theft
* Shellcode execution

However, this case does not match malicious patterns.

### Expected Electron Behaviour
Electron applications frequently create remote threads between their own processes.

### Safe Conditions
* Same binary
* Same user
* Same signed module
* No suspicious memory regions
* No privilege mismatch

### Recommended Detection Tuning
Add a baseline condition:
```
SourceImage == TargetImage 
AND Image is a verified Electron/Chromium binary
```
This prevents false positives for VS Code, Slack, Teams, Discord, etc.

## 4. SOC Classification

* **Classification:** Benign Positive — legitimate Electron multi‑process thread creation.
* **Risk Rating:** Informational (Low)
* **SOC Action:** Catalogue under *Developer Tooling & Multi‑Process Application Baseline*. No further investigation required.

## Final Notes
This analysis demonstrates how Electron‑based applications can trigger high‑severity Sysmon events that resemble process injection, even though the behaviour is completely legitimate. Understanding these patterns is essential for reducing noise and improving detection accuracy in a SOC environment.
