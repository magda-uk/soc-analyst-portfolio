# SOC Methodology

This document outlines the core methodology used in a Security Operations Centre (SOC) for detection, triage, investigation, hunting, and response.

---

## 1. Detection Engineering
- Build analytics rules based on real attack behaviours.
- Use anomaly detection for early warning signals.
- Map all detections to MITRE ATT&CK.
- Validate rules using KQL testing checklist.
- Document each detection with investigation and response steps.

---

## 2. Triage Methodology
- Validate alert context (user, device, IP).
- Check baseline vs anomaly.
- Identify false positives quickly.
- Prioritise alerts using severity framework.
- Escalate only when behaviour is abnormal or malicious.

---

## 3. Investigation Methodology
- Pivot across datasets (auth, process, network).
- Build a timeline of events.
- Identify root cause and entry point.
- Validate persistence, lateral movement, or exfiltration.
- Document findings clearly.

---

## 4. Threat Hunting Methodology
- Start with a hypothesis (e.g., “Encoded PowerShell indicates execution”).
- Use multi‑dataset correlation.
- Build timelines using hunting queries.
- Identify patterns, clusters, and anomalies.
- Feed findings back into detection engineering.

---

## 5. Response Methodology
- Contain the threat (disable account, isolate device).
- Eradicate malicious artefacts.
- Recover systems safely.
- Conduct lessons learned.
- Update detections and playbooks.

---

## 6. Continuous Improvement
- Review alerts weekly.
- Tune rules to reduce noise.
- Add new detections based on threat intel.
- Maintain documentation in `6.documents/`.
