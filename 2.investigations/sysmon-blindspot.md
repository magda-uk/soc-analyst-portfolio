## 1. Executive Summary
This investigation details the triage of a blocked network connection on a Windows endpoint. The objective was to correlate a high-priority antivirus alert (invalid SSL certificate) with OS-level network telemetry (Sysmon). The investigation confirmed that highly effective Endpoint Detection and Response (EDR) prevention mechanisms can create "blind spots" in standard logging tools due to early interception.

## 2. Incident Timeline (UTC)
* **12:21:04 UTC:** The user's browser (`msedge.exe`) attempted an HTTPS connection to `r.msftstatic.com`.
* **12:21:04 UTC:** EDR module (Kaspersky Safe Browsing) intercepted the TLS handshake, identified an invalid certificate, and instantly severed the connection.
* **12:21:xx UTC:** OS-level telemetry (Sysmon) failed to register Event ID 3 (Network Connection) because the connection was aborted before the operating system could establish it.

The initial alert was generated by the endpoint security software. The alert explicitly stated the process, the destination object, and the reason for the block.

## 4. Telemetry Investigation (Sysmon)
Standard SOC procedure requires validating endpoint alerts against system logs to understand the full scope of the activity. 

**Hunting Steps:**
1. Accessed `Microsoft-Windows-Sysmon/Operational` logs via Event Viewer.
2. Applied a filter for **Event ID 3** (Network connections) and **Event ID 22** (DNS Queries).
3. Adjusted the search timeframe to account for the local time (BST) versus the UTC timestamps in Sysmon.
4. Queried the filtered logs for the specific destination domain (`msftstatic`).

![No results](/2.investigations/images/no-results.png)
> *Figure 2: Sysmon logs showing zero results for the queried domain at the exact time of the incident.*

## 5. Conclusion & SOC Recommendations
Despite applying the correct filters, Sysmon showed absolutely no record of this connection attempt. 

**Root Cause of the Telemetry Gap:**
Modern security tools operate at a deep kernel level using mechanisms like the Windows Filtering Platform (WFP). The EDR inspected the certificate and killed the process in milliseconds. Because the digital handshake never finished, the OS never considered the connection established, leaving Sysmon "blind" to the event.

**Key Takeaways:**
* **Trusting the Absence of Data:** In forensic analysis, finding nothing can confirm the efficiency of an EDR's early-blocking mechanism.
* **Correlation is Mandatory:** Relying solely on a single source of truth (e.g., only checking Sysmon) can lead to missed alerts. A robust SOC workflow requires correlating data from both OS telemetry and dedicated security agents.
